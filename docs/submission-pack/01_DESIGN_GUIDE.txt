1. PURPOSE AND SCOPE
================================================================================

This Design Guide defines how Azure Bay looks and feels across:

  • Public marketing and booking website
  • Guest account surfaces (My bookings, Messages, Stay portal)
  • Staff portal (Front desk, Dining, Housekeeping, Inventory, Settings, etc.)

It is the visual companion to the Developer Guide and User Guide. Implementation
must reuse one design system — do not invent a second look for the admin area.

================================================================================
2. BRAND STORY AND POSITIONING
================================================================================

Brand name: Azure Bay Hotel & Resort
Tone: Calm luxury by the sea — confident, warm, never loud or “startup purple.”
Promise: Seamless stay discovery online; reliable operations for the house staff.

Brand signals on first viewport:
  • Resort name / logo as a hero-level presence (not only tiny nav text)
  • One clear headline, one supporting line, one primary CTA group
  • One dominant full-bleed ocean / resort photograph

Avoid (project rule):
  • Generic purple-on-white SaaS look
  • Flat single-color pages with no atmosphere
  • Card spam in the hero
  • Detached promo stickers floating on hero media

3. DESIGN PRINCIPLES
================================================================================

P1. One composition first
    The home first viewport reads as one scene, not a dashboard of widgets.

P2. Brand first
    After removing the nav, the page should still feel like Azure Bay.

P3. One job per section
    Each band has one headline and one supporting sentence.

P4. Real visual anchors
    Photography of rooms, sea, dining, spa — not abstract blobs as the main idea.

P5. Reuse the system
    Public site and portal share navy, gold, cream, rounded-2xl surfaces, pills.

P6. Motion with purpose
    Tide-like easing, reveal text, peek carousels — presence, not noise.
    Honor prefers-reduced-motion.

P7. Least privilege is visible
    Staff see only the tabs they need; fewer controls = clearer design.

4. COLOR SYSTEM
================================================================================

Primary tokens (implementation: client/src/index.css Tailwind theme):

  Navy (authority, text, primary actions outline):
    --color-navy ≈ #0b1f33
    Darker navy for depth / hero overlays ≈ #071b2b

  Gold (accent, primary CTA fills, stars, focus rings):
    --color-gold ≈ #f2c078

  Cream (page canvas, soft panels):
    Background cream / sand ≈ #fbfaf7 / #faf8f4

  White: cards and elevated panels on cream
  Muted text: soft slate for secondary copy (readable on cream)

Usage rules:
  • Primary CTA on public site: gold fill + navy text (high hospitality warmth)
  • Strong navy fill for secondary / confirm staff actions
  • Borders: navy at low opacity (≈ 8–15%), never harsh black rules
  • Focus visible: gold outline / ring

5. TYPOGRAPHY
================================================================================

Display / headlines: Serif display (project font-display) — editorial, resort feel.
Body / UI: Clean sans for forms, tables, nav, portal labels.

Hierarchy examples:
  • H1 room name / page titles: large display, navy
  • Section titles: display ~2xl
  • Eyebrows: small uppercase or small label above titles
  • Body: sm–base, leading-relaxed / leading-7 for guest reading
  • Meta: xs–sm muted (prices secondary line, timestamps)

Do not default the entire product to Inter-only marketing look; keep display
contrast between serif headlines and sans UI.

6. SPACING, RADIUS, ELEVATION
================================================================================

Spacing: prefer 8px rhythm (gap-2, gap-3, gap-4, section py-14 / py-16).
Page wrap: consistent max-width container (page-wrap class).

Radius:
  • Cards / panels: rounded-2xl
  • Buttons / chips: rounded-full (pill) for primary actions
  • Image thumbs: rounded-lg to rounded-2xl

Elevation:
  • Soft navy-tinted shadows, e.g. shadow-[0_16px_40px_rgba(7,27,43,0.08)]
  • Avoid multi-layer neon glows

================================================================================
7. ICONOGRAPHY AND MOTION
================================================================================

Icons: lucide-react — thin, consistent stroke; navy or muted; gold for rating stars.

Motion vocabulary (client/src/lib/motion.js):
  • easeTide / easeFlow
  • duration.ui / duration.micro
  • RevealText, PeekViewport carousels, Preloader, RouteWipe
  • Custom cursor labels on intentional interactive media (desktop)

Reduced motion: shorten or disable decorative motion; keep usability intact.

8. COMPONENT LIBRARY (DESIGN SYSTEM)
================================================================================

Shared UI (client/src/components/ui/ and related):

  Buttons: PillButton, CircleButton, gold / navy / outline / light variants
  Badge: filled and outline chips (amenities, status)

  BlurImage / SmartImage: progressive media

  Dashboard SoftRow / Panel / cardClass: portal list rows on cream

Staff shell: DashboardShell — sidebar + main; calm motion optional.

10. BOOKING AND CONVERSION UX
================================================================================

  • Sticky mini booking bar after hero scroll (public)
  • Auth gate on Book / Check availability when unsigned
  • Price calendar respects booking window + sold-out nights
  • Booking flow /rooms → detail → /booking/:roomId
  • My bookings: cancel, request date change via Messages

Design goal: never trap the guest; always show why a night is blocked.

11. STAFF / ADMIN PORTAL UX
================================================================================

Visual language:
  • Same cream canvas, navy type, gold CTAs
  • Panel titles with display font
  • Soft bordered rows (cardClass) for lists
  • Tables / kanban for desk and housekeeping
  • Toasts for success/failure — no silent failures

Key screens:
  Overview (charts + review moderation)
  Front desk (stays table, actions sheet, invoice)
  Messages (thread list + conversation)
  Dining board (Kitchen / Tables; Menu/Reports for managers)
  Inventory (types + physical rooms + amenity chips + media picker)
  Media library
  Housekeeping kanban
  Maintenance tickets
  Staff (admin) — password issue card
  Settings (admin) — tax, window, stay policies

12. ROLE-BASED INTERFACE CLARITY
================================================================================

Design must make least privilege obvious:

  Admin: Staff + Settings visible
  Manager: ops tabs; no Staff/Settings
  Receptionist: desk; Dining Kitchen+Tables only (no Menu/Reports)
  Housekeeping: own queue emphasis
  Guest: Stay / Profile / Messages link — not hotel ops

13. RESPONSIVE AND MOBILE BEHAVIOR
================================================================================

  Desktop ≥1200: full compositions, side booking card on room detail
  Tablet: booking bar wraps; carousels peek
  Mobile ≤767: hamburger nav; vertical booking; room mobile reserve bar;
               portal stacks; tables scroll horizontally if needed

Sticky Check Availability / mini bar: respect safe areas; do not cover CTAs.

14. ACCESSIBILITY
================================================================================

  • Keyboard reachability for controls
  • Visible focus (gold outline)
  • Labels on inputs; associated errors
  • Meaningful alt text on room/experience images
  • Contrast on photo overlays (navy scrim / cream panels)
  • Reduced-motion path
  • Aria labels on icon-only circle buttons and star ratings

16. EMPTY, LOADING, AND ERROR STATES
================================================================================

  Skeleton: loading catalogs, reports, policies, reviews
  EmptyState: no amenities, no published reviews, empty HK board
  ErrorState: failed list loads with human message
  InlineError: field-level booking issues

Never show a blank white screen for expected empty data.
